## Правила: state vs eval

`browser-use state` дампит весь DOM страницы. Маркетплейсы — очень тяжёлые SPA с тысячами элементов. State занимает 10-30 секунд и забивает контекст.

### Делай state

- В начале работы с каждой новой площадкой (определить структуру)
- Когда eval возвращает неожиданный результат (DOM изменился)
- При навигации на новую страницу (поиск → карточка товара)
- Когда нужно найти индекс элемента для `click`

### НЕ делай state

- Для получения цены (используй eval)
- Для получения названия товара (используй eval)
- Для проверки загрузки страницы (используй eval)
- Для извлечения списка товаров (используй eval)
- Между одинаковыми операциями (поиск → поиск → поиск)

### Быстрые eval-проверки вместо state

```bash
# Загрузились товары?
browser-use eval "document.querySelectorAll('[class*=\"product-card\"], [class*=\"tile\"], [class*=\"search-result\"]').length > 0"

# Цена конкретного товара
browser-use eval "document.querySelector('[class*=\"price\"]')?.textContent?.match(/[\\d\\s]+/)?.[0]?.trim()"

# Название товара
browser-use eval "document.querySelector('h1, [class*=\"title\"]')?.textContent?.trim()?.substring(0, 100)"
```

## Оценка «Выгодная ли покупка?»

### Методика оценки

1. **Сравни с средней ценой** — если ниже средней на 15%+ — выгодно
2. **Проверь историю цен** — если цена близка к минимуму — отлично
3. **Учти цену за единицу** — большая упаковка часто дешевле за единицу
4. **Проверь аналоги** — может, похожий товар стоит в 2 раза дешевле
5. **Учти доставку** — дорогой товар с бесплатной доставкой может быть выгоднее дешёвого с платной

### Вердикт

| Оценка | Условие |
|--------|---------|
| Отличная цена | ниже минимума за 6 месяцев или ниже средней на 20%+ |
| Хорошая цена | ниже средней на 5-20% |
| Нормальная цена | в пределах +/- 5% от средней |
| Дорого | выше средней на 5-20% |
| Переплата | выше средней на 20%+ или выше максимума за 6 месяцев |

### Использование web_search для оценки

```
web_search "цена [название товара] отзывы обзор 2025 2026"
```

Ищи обзоры и сравнения — они часто указывают справедливую цену.

## Обработка ошибок

| Проблема | Решение |
|----------|---------|
| Товар не найден на одной из площадок | Напиши «На [площадка] товар не найден». Сравни только найденные. |
| CAPTCHA на Wildberries | Подожди 30 секунд, обнови. Попроси пользователя пройти вручную в headed-режиме. |
| Страница долго грузится | Увеличь sleep до 5-6 секунд. Все три площадки — тяжёлые SPA. |
| Цена не извлекается | Сделай `browser-use state` для актуальной структуры DOM. Селекторы могли измениться. |
| Разные товары в выдаче | Уточни запрос: добавь бренд, модель, артикул. Сравнивай только идентичные товары. |
| Модальное окно блокирует | `browser-use eval "document.querySelector('[class*=\"modal\"], [class*=\"popup\"]')?.querySelector('[class*=\"close\"], [aria-label=\"Закрыть\"]')?.click()"` |
| Сессия зависла | `browser-use close --all`, начни заново. |
| Wildberries показывает регион другой | Выбор города — через eval кликнуть на город в шапке и выбрать нужный. |
| Ozon: нет результатов | Ozon чувствителен к кириллице в URL. Попробуй латиницу или другой формат запроса. |
| Яндекс Маркет: требуется вход | Некоторые данные видны только авторизованным. Попроси пользователя войти. |
| Цены в разной валюте | Все три площадки показывают цены в рублях. Если видишь другую валюту — это баг парсинга. |
| Некорректные символы в URL | Кодируй кириллицу: `encodeURI('ноутбук')` → `%D0%BD%D0%BE%D1%83%D1%82%D0%B1%D1%83%D0%BA` |
| «Element not found» после навигации | DOM перерисовался — делай `state` заново для свежих индексов. |

## Использование image_analysis

Для анализа фотографий товаров (полезно при сопоставлении одинаковых товаров):

```bash
# Получить URL изображения товара
browser-use eval "document.querySelector('[class*=\"image\"] img, [class*=\"photo\"] img, img[class*=\"product\"]')?.src"
```

Затем используй `image_analysis` с параметрами:
- `imageSource`: URL изображения товара
- `prompt`: «Опиши товар на фото: категория, бренд, модель, цвет, размер, состояние упаковки»

## Оптимизация для повторных запросов

Если пользователь просит сравнить цены на несколько товаров подряд:

1. **Не закрывай браузер** между запросами — переходи по новому URL поиска
2. **Используй один профиль** для сохранения авторизации: `browser-use --profile "shopper"`
3. **Кешируй структуру DOM** — если площадка не обновлялась, селекторы те же
4. **Группируй запросы** — если 3+ товара, спрашивай «Сравнить все сразу или по очереди?»

## Советы

1. **Всегда `close --all` первым** — старые сессии — причина #1 зависаний
2. **Жди 4-5 секунд** после навигации — маркетплейсы — очень тяжёлые SPA
3. **Проверяй модалки перед действиями** — Wildberries и Ozon любят всплывающие окна
4. **Используй eval вместо state** — eval в 10 раз быстрее и не забивает контекст
5. **Сравнивай цену за единицу** — а не полную цену, для честного сравнения
6. **Проверяй отзывы на накрутку** — особенно на Wildberries
7. **Учитывай стоимость доставки** — дорогой товар с бесплатной доставкой может быть выгоднее
8. **Проверяй историю цен** перед покупкой — скидка может быть ненастоящей
9. **Не забывай про аналоги** — похожий товар другого бренда может быть в 2 раза дешевле
10. **Упрощай поисковые запросы** — «Ноутбук ASUS VivoBook 15 X515EA-BQ» → «ASUS VivoBook 15 X515EA»
