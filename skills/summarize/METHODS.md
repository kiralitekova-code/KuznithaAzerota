# Методы сжатия: подробное руководство

Развернутое описание методов, на которые ссылается [SKILL.md](SKILL.md). Используй этот файл, когда задача требует большего, чем однопроходное сжатие короткого текста.

## Экстрактивный vs абстрактивный подход

Два фундаментальных способа сжатия. Понимание разницы определяет выбор метода.

### Экстрактивный

Сжатие = выбор ключевых предложений из оригинала дословно. Новых формулировок не создаётся.

**Когда применять:**
- Нужна максимальная точность (юридические, медицинские, научные тексты)
- Стиль и формулировки автора важны (цитирование, доказательная база)
- Первый этап двухэтапного pipeline для длинных документов

**Как работает:**
1. Разбей текст на предложения.
2. Оцени значимость каждого (по частоте ключевых слов, положению в тексте, похожести на «центральную» мысль).
3. Выбери top-k предложений, сохранив порядок из оригинала.

**Плюс:** нулевой риск галлюцинаций — берём только то, что есть.
**Минус:** выжимка может быть связной неудачно; не обобщает, а выхватывает.

### Абстрактивный

Сжатие = собственная переформулировка. Агент пишет выжимку своими словами, создавая новые предложения, которых не было в оригинале.

**Когда применять:**
- Нужна связная, читаемая выжимка (статьи, отчёты, обзоры)
- Сжатие сильнее, чем позволяет экстракция (например, 10 страниц в 3 предложения)
- Объединение нескольких чанков в Map-Reduce (reduce-этап)

**Плюс:** лаконичнее, лучше читается, обобщает.
**Минус:** выше риск искажения — нужна сверка с оригиналом.

### Когда какой

| Критерий | Экстрактивный | Абстрактивный |
|----------|:-------------:|:-------------:|
| Юридический / медицинский текст | ✅ | ⚠️ осторожно |
| Новостная статья, обзор | ✅ | ✅ |
| Сильное сжатие (10× и больше) | ❌ | ✅ |
| Нужны дословные цитаты | ✅ | ❌ |
| Связный пересказ для чтения | ❌ | ✅ |
| Map-этап (обработка чанков) | ✅ | ✅ |
| Reduce-этап (объединение) | ❌ | ✅ |

## Двухэтапный pipeline

Для очень длинных документов: сначала экстрактивно выбрать самое важное, потом абстрактивно сжать выбранное.

### Процедура

```
Этап 1 — Экстракция (через code_execution):
  1. Разбить текст на предложения.
  2. Вычислить оценку каждого предложения:
     - TF-IDF по ключевым словам текста
     - Близость к «идеальному предложению» (среднее по частотам)
     - Бонус за позицию (первое и последнее предложение секции)
  3. Выбрать top-k предложений (k = целевой_объём / средняя_длина)
  4. Вернуть выбранные предложения в исходном порядке.

Этап 2 — Абстракция:
  1. Прочитать выбранные предложения как новый «документ».
  2. Сжать абстрактивно в связную выжимку.
  3. Сверить с оригиналом (каждое утверждение выводимо?).
```

**Когда применять:** документ > 10 000 слов и нужен связный пересказ в 1 страницу. Экстракция отсекает шум, абстракция даёт читаемость.

**Мини-пример:** Технический отчёт на 40 страниц. Экстрактивный этап выбирает ~30 ключевых предложений (выводы, цифры, рекомендации). Абстрактивный этап превращает их в 8 буллетов выжимки + TL;DR.

## Map-Reduce

Метод для документов, которые не помещаются в контекст целиком. Разделяй и объединяй.

### Процедура

```
ШАГ 1 — Разбиение (chunking):
  - Разбить документ на чанки по смысловым границам:
    * по заголовкам секций (предпочтительно)
    * по абзацам, группируя по ~800–1500 слов
  - Сохранить структуру (название секции → её чанк).
  - Чанки не должны перекрываться (дубликаты = искажение пропорций).

ШАГ 2 — Map (сжатие каждого чанка):
  FOR EACH чанк:
    - Сжать в 3–5 предложений.
    - Сохранить ключевые цифры, имена, даты дословно.
    - Помечать источник чанка (номер секции).
  Результат: набор чанковых выжимок.

ШАГ 3 — Reduce (объединение):
  - Если суммарная длина выжимок помещается в контекст:
      сжать их абстрактивно в финальную выжимку за один проход.
  - Если нет:
      разбить выжимки на группы → сжать каждую группу (reduce уровня 2)
      → объединить группы в финальную выжимку (reduce уровня 3).

ШАГ 4 — Проверка:
  - Каждое утверждение финальной выжимки выводимо из чанковых выжимок?
  - Чанковые выжимки выводимы из оригинала?
  - Цифры не потерялись на этапах?
```

**Псевдокод:**

```python
def map_reduce_summary(document, target_length):
    chunks = split_by_sections(document)          # Шаг 1
    if len(chunks) == 1:
        return abstractive_summarize(chunks[0])   # короткий текст — в один проход

    chunk_summaries = [abstractive_summarize(c) for c in chunks]   # Шаг 2 (map)

    combined = "\n".join(chunk_summaries)         # Шаг 3 (reduce)
    while len(combined) > target_length * 4:      # если слишком длинно — ещё уровень
        groups = group_summaries(combined)
        chunk_summaries = [abstractive_summarize(g) for g in groups]
        combined = "\n".join(chunk_summaries)

    final = abstractive_summarize(combined)       # финальная выжимка
    return final
```

**Контроль потерь:** На каждом уровне reduce проверяй, что ключевые цифры и названия секций сохранились. Map-Reduce имеет риск «размытия» — при объединении выжимок важные детали низкого уровня могут утонуть. Решение: на map-этапе явно требовать сохранения всех чисел и имён.

## Иерархическое сжатие

Вариант Map-Reduce для структурированных документов (отчёты, регламенты, книги с главами). Использует естественную иерархию вместо искусственных чанков.

### Процедура

```
УРОВЕНЬ 0 — Секции документа (главы / разделы).
УРОВЕНЬ 1 — Выжимка каждой секции (3–5 предложений на секцию).
УРОВЕНЬ 2 — Общая выжимка из выжимок секций.
```

**Отличие от Map-Reduce:** чанки = осмысленные секции, а не отрезки по N слов. Результат лучше структурирован и легче проверяется.

**Мини-пример:**

```
Документ: Годовой отчёт компании (5 глав)

УРОВЕНЬ 1 — выжимки по главам:
  Глава 1 «Финансы»:   выручка +18% до 4,2 млрд ₽, маржа упала с 22% до 19%
  Глава 2 «Команда»:   штат вырос с 120 до 165, текучесть 8% (ниже рынка)
  Глава 3 «Продукт»:   запущены 2 фичи, NPS поднялся с 41 до 52
  Глава 4 «Рынки»:     доля в РФ 12%, вышли в Казахстан (1,5% доля)
  Глава 5 «Риски»:     зависимость от одного поставщика (40% сырья)

УРОВЕНЬ 2 — общая выжимка:
  Год успешный: рост выручки и команды, но маржа под давлением.
  Главный риск — концентрация на поставщике (40% сырья).
  Новый рынок (Казахстан) пока незначителен.
```

## Адаптация формата под цель

Один и тот же источник сжимается по-разному в зависимости от того, зачем пользователю выжимка.

| Цель пользователя | Формат | Объём |
|-------------------|--------|-------|
| «Понять за 1 минуту» | TL;DR + 3–5 тезисов | ~100 слов |
| «Прочитать за 5 минут» | TL;DR + тезисы + контекст | ~300 слов |
| «Выжимка для решения» | Вывод + аргументы + «что делать» + неопределённость | ~250 слов |
| «Только action items» | Чеклист с @владелец и сроком | минимальный |
| «Подробный пересказ» | По секциям, без воды | ~30% оригинала |
| «Для презентации» | Тезисы-слайды, по буллету на слайд | ~50 слов/слайд |

Если цель не названа — задай один вопрос: «Тебе понять суть, принять решение или получить action items?» Один вопрос лучше угадывания.
