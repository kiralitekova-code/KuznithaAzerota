# Lateral Thinking Techniques and Decision Frameworks

When standard ideation stalls, use these structured techniques to generate ideas from unexpected angles.

## Lateral Thinking Techniques

### Random Entry

Pick a random, unrelated concept. Force a connection to the problem.

**How:**
1. Pick a random noun (use the first object you see, or ask the user to name one)
2. List 5 properties of that object
3. For each property, ask: "How does this relate to the problem?"
4. Extract useful ideas from even absurd connections

**Example:** Naming a project management tool. Random word: "umbrella"
- Covers you from rain → "tool that shields you from missed deadlines" → "Shield" or "Canopy"
- Folds up small → "tool that stays out of your way" → minimal interface concept
- Shared in a group → "one tool for the whole team" → collaboration angle
- Different colors → "customize for each project" → personalization angle

### Provocation

State something deliberately wrong or absurd. Extract the useful insight.

**How:**
1. State the opposite of the conventional wisdom: "What if we did the exact opposite?"
2. Or state an absurd constraint: "What if we had zero budget?" / "What if we had one hour?"
3. List what the provocation implies
4. Extract real, useful ideas from the implications

**Example:** "What if our restaurant had no menu?"
- Implies: customers don't choose, chef decides → tasting menu concept
- Implies: no printed menu costs → environmental angle
- Implies: surprise factor → market as "adventure dining"
- Useful idea: rotating surprise menu as a differentiator

### SCAMPER

Systematic transformation of an existing idea. Apply each letter:

| Letter | Transform | Question |
|--------|-----------|----------|
| **S** — Substitute | Replace a component | "What if we used [different material/technology/person]?" |
| **C** — Combine | Merge with something else | "What if we combined this with [unrelated thing]?" |
| **A** — Adapt | Borrow from elsewhere | "What has solved a similar problem in a different domain?" |
| **M** — Modify/Magnify | Scale something up/down | "What if we made this 10x bigger/smaller/faster/cheaper?" |
| **P** — Put to other use | Use for different purpose | "Who else could use this? What else could this do?" |
| **E** — Eliminate | Remove something | "What if we removed [core feature]? What's left?" |
| **R** — Reverse/Rearrange | Flip the order | "What if we did this backwards? What if the customer came to us?" |

**Example for a meal delivery service:**
- **Substitute**: What if chefs cooked in customers' kitchens instead of a central kitchen? → personal chef service
- **Combine**: What if we combined meal delivery with grocery shopping? → ingredients + recipe cards (HelloFresh)
- **Eliminate**: What if we eliminated choice? → surprise daily meal, no menu

### Assumption Inversion

List the implicit assumptions, then invert each one.

**How:**
1. List 5 things "everyone knows" about this problem
2. Invert each assumption
3. Ask: "What kind of solution does the inverted world need?"
4. Are any of those solutions viable in the real world?

**Example for education:**
1. Assumption: Learning happens in classrooms → Inversion: Learning happens everywhere → Mobile-first, location-independent education
2. Assumption: Teachers deliver content → Inversion: Students discover content → Self-directed learning platform
3. Assumption: Education takes years → Inversion: Education is instant → Microlearning, just-in-time skill acquisition

### Analogy Mapping

Solve the problem by mapping it to an entirely different domain.

**How:**
1. "How would [profession/system] handle this?" Pick from:
   - A chef, architect, musician, general, doctor, journalist
   - A city planner, game designer, airline, hospital, factory
2. List the key principles of that domain
3. Map each principle to your problem
4. Extract applicable ideas

**Example:** "How would a restaurant handle our customer support?"
- Menu (standard options) → FAQ with standard responses for common issues
- Specials (daily features) → Proactive updates about new features/known issues
- Maitre d' (greeter) → Personalized welcome and triage
- Kitchen (back of house) → Internal knowledge base agents use
- Tip (reward) → Loyalty/credit for patient customers during outages

## Decision Frameworks

When converging from multiple options to a decision.

### Criteria Weighting

1. List the decision criteria the user cares about (ask: "What matters most to you?")
2. Weight each criterion: must-have (3), nice-to-have (2), bonus (1)
3. Score each option against each criterion: strong (3), moderate (2), weak (1)
4. Multiply weight × score for each cell
5. Sum for each option

Present as a table, highlight the winner, note where it's weakest.

### Reversibility Test

For each option, ask: "If we choose this and it's wrong, how hard is it to undo?"

| Option | Reversibility | Risk of choosing |
|--------|--------------|-----------------|
| Easy to undo | Low risk | Just try it |
| Hard to undo | High risk | Validate assumptions first |
| Irreversible | Maximum risk | Only choose with strong evidence |

Prefer reversible options. If all options are irreversible, invest more time in validation.

### Regret Minimization

Ask: "If I'm 80 years old looking back, which option would I regret NOT trying?"

This cuts through analysis paralysis. It surfaces the user's real values, not just their logical analysis.

## Validation Patterns

After choosing an idea, validate the riskiest assumption cheaply.

| Riskiest Assumption | Cheap Validation |
|---------------------|------------------|
| "People want this" | Talk to 5 potential users. Not friends |
| "People would pay for this" | Create a landing page with a price. See if anyone clicks buy |
| "We can build this" | Build the hardest part first. Not a prototype — the real hardest part |
| "This scales" | Calculate unit economics at 10x current volume |
| "We're better than alternatives" | List on a comparison site. Track actual preference |
| "The market is big enough" | Count the addressable audience with real data, not guesses |

Time-box validation: 1-5 days. If you can't validate in a week, you're overthinking it.
